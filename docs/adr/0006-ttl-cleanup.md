# ADR-0006: TTL-очистка неактивных вёдер

- **Статус:** accepted
- **Дата:** 2026-09-21

## Контекст

Каждый уникальный логин/пароль/IP создаёт ведро. В production это
могут быть миллионы вёдер. Хранить их вечно — утечка памяти.

## Решение

Фоновая goroutine удаляет вёдра, к которым не обращались дольше `TTL`
(по умолчанию 10 минут). Интервал очистки = `TTL / 2`, чтобы ведро
жило «чуть дольше» TTL, но не сильно.

Реализация в `internal/limiter/storage.go`:
- поле `entry.lastActivity` обновляется при каждом обращении;
- `cleanupLoop` просыпается каждые `TTL/2` и удаляет устаревшие;
- корректно завершается по `ctx.Done()`.

## Последствия

- **+** Память ограничена сверху (число активных ключей × размер ведра).
- **+** Graceful shutdown работает.
- **−** Возможны «фантомные» сбросы: если пользователь вернётся через
  TTL+1 минуту, его старое ведро уже удалено, но лимиты не нарушены.
