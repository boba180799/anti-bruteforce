# ADR-0009: Конфигурация через переменные окружения

- **Статус:** accepted
- **Дата:** 2026-09-21

## Контекст

Параметры сервиса (адреса портов, лимиты, TTL) нужно передавать при
старте. Возможные форматы: YAML-файл, TOML, JSON, CLI-флаги,
переменные окружения.

## Рассмотренные варианты

1. **YAML-файл.** Человекочитаемо, но требует ещё один файл и парсер.
   В контейнерах файл надо монтировать.
2. **CLI-флаги.** Хороши для ручного запуска, но неудобны в Kubernetes
   (длинные командные строки) и docker-compose (healthcheck, secrets).
3. **Переменные окружения.** Стандарт индустрии (12-factor app).
   Работают одинаково в Docker, k8s, systemd, локально.

## Решение

Выбран **вариант 3**: только env-переменные. Загрузка в
`internal/config/config.go` через хелперы `envOr`, `envFloat`,
`envDuration`. Дефолты соответствуют требованиям ТЗ.

## Последствия

- **+** Совместимо с 12-factor app.
- **+** Не нужны файлы конфигов в образе.
- **+** Легко передавать секреты через Docker secrets / k8s Secrets.
- **−** Сложные структуры (списки, вложенные объекты) передавать неудобно.
- **−** Нет валидации (например, `LOGIN_LIMIT=abc` молча превратится
  в дефолт). Митигация — отдельная задача: `Validate()` на `Config`.
