# ADR-0004: Whitelist имеет приоритет над blacklist

- **Статус:** accepted
- **Дата:** 2026-09-21

## Контекст

IP-адрес может одновременно попасть в whitelist (доверенные подсети)
и в blacklist (запрещённые). Возникает вопрос: какое правило победит?

## Рассмотренные варианты

1. **Blacklist побеждает.** Безопаснее: один запрет перекрывает всё.
   Но: чтобы разрешить офис, придётся сначала найти и удалить широкое
   blacklist-правило, которое случайно захватило офисную подсеть.
2. **Whitelist побеждает.** Администратор явно выразил доверие —
   пусть оно перекрывает запрет. Это стандарт в файрволах (Cisco ACL,
   iptables `-I` в начало цепочки, Cloudflare WAF).
3. **Ошибка при пересечении.** Заставлять админа явно разрешать
   конфликт — но это усложняет API и повышает трение.

## Решение

Выбран **вариант 2**: whitelist имеет приоритет. Реализовано в
`usecase.CheckAttempt` — правило `whitelistRule` идёт первым в цепочке.

## Последствия

- **+** Администратор может быстро разрешить доступ к сервису
  доверенной подсети, не трогая blacklist.
- **+** Совпадает со стандартной практикой сетевой безопасности.
- **−** Потенциальная «дыра»: если whitelist слишком широкий,
  он перекроет узкий blacklist. Митигация — валидация и code review
  при добавлении правил.
