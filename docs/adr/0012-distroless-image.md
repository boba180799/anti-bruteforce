# ADR-0012: Distroless как базовый образ

- **Статус:** accepted
- **Дата:** 2026-09-21

## Контекст

Docker-образ сервиса должен быть минимальным и безопасным.
Возможные базовые образы: alpine, debian-slim, scratch, distroless.

## Рассмотренные варианты

1. **alpine** (~7 МБ). Популярен, есть shell и пакетный менеджер —
   удобно отлаживать, но это же и минус: атакующий получит shell.
2. **debian-slim** (~75 МБ). Ещё хуже.
3. **scratch** (0 МБ). Пустой образ. Не содержит CA-сертификатов,
   `/etc/passwd`, таймзон — надо тащить руками.
4. **gcr.io/distroless/static-debian12:nonroot** (~2 МБ). Только
   бинарь и минимальный набор файлов: CA-сертификаты, `/etc/passwd`
   с пользователем `nonroot`, libc для статических бинарей.

## Решение

Выбран **вариант 4**: `gcr.io/distroless/static-debian12:nonroot`.

Dockerfile — multi-stage:
- **builder:** `golang:1.26-alpine`, компиляция с `CGO_ENABLED=0`.
- **runtime:** distroless, только `/anti-bruteforce` и `/cli`.

Запуск от пользователя `nonroot:nonroot`.

## Последствия

- **+** Размер образа ~10 МБ (бинарь + 2 МБ базы).
- **+** Нет shell, нет пакетного менеджера — атакующий почти ничего
  не сможет сделать, даже получив RCE.
- **+** Нет `latest`-тегов в базовых образах (пиннинг digest).
- **−** Нельзя зайти в контейнер `docker exec sh` — только
  `docker exec /anti-bruteforce --help`. Отладка сложнее.
- **−** Если понадобится TLS-клиент — сертификаты уже в distroless,
  но нестандартные CA надо копировать.
